# 04 — Legacy setup with a token — developer cases

Use case: [04-legacy-setup-with-token.md](../04-legacy-setup-with-token.md). Contract: [api-contract.md](../api-contract.md#post-apirestaurantssetup). Fixtures: [README.md](./README.md#fixtures).

All requests: `POST /api/restaurants/setup` with `Authorization: Bearer <token>` and body "full" **without** `phone` unless stated, using different values from the restaurant's current ones (name `Changed Name`, etc.). Snapshot the caller's restaurant, config, zones, tables, channels and user row before each case. **Reset REST-LEG to onboarding not done** (`isOnboardingDone = 0`) before each case that uses OWN-LEG. Cases tagged *Fails until ONB-D1 is fixed* assert the target checks (account → restaurant found → restaurant switched off → role → onboarding done); the others pass today and after the fix.
