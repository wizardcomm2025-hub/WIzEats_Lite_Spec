Floors & rooms

Floors and rooms for Room Service. It copies the zones and tables module, but the GUID conversion was never added, so most of it fails today.

v1 scope

Two use cases: manage floors and manage rooms. See the README. The spec records today's behaviour; ROOM-D1 to D3 keep the current rules as accepted risks.

How it works end-to-end

With Room Service on (RST), the owner's menu shows Floor Management and Room Management. FloorManagementScreen lists floors through getFloorDetails and saves through floorSave. RoomConfigScreen lists rooms per floor through getRoomsDetails and saves through roomSave. RoomService uses the IDs as sent. Unlike TableService, it has no hex2bin.

What matters where you sit

POS API

  • Every lookup by floorId / roomId compares hex against binary, so updates give a 500 and filters return [].
  • Creating a room inserts floorId as sent. A 32-character hex is too long (500); a short string creates an orphan room.
  • A roomId filter is ambiguous with orders.roomId (500).
  • No role checks; the Room Service setting isn't checked; no rate limits.

Data — MySQL

  • floors and rooms, both keyed by binary(16).
  • The list returns active rooms only, so an inactive room can't be found again.

POS app

  • Number(r.floorId) === selectedFloor.floorId, the same fault as TBL-D1.
  • Failed adds and renames are silent; a failed switch shows the server message.

Super-admin panel

No floor or room pages. The panel only switches Room Service (RST).

Integrations

None. Import (IMPEX) is today the only working way to create rooms.

Accepted risks (do not "fix" without a new decision)

  • ROOM-D1: the broken GUID handling. Only adding a floor and listing work.
  • ROOM-D2: no role check and no Room Service check in the API.
  • ROOM-D3: orphan rooms, any capacity, 500s for long names, inactive rooms unlisted.
