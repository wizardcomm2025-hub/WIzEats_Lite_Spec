Zones & tables

Seating areas and their tables. There are two save endpoints that both create and update, two list endpoints, two app screens, and two panel pages. Home reads the result through the restaurant details endpoint.

v1 scope

Three use cases: manage zones in the app, manage tables in the app, and manage zones and tables in the panel. See the README. The spec records today's behaviour; TBL-D1 to D4 keep the current rules as accepted risks.

How it works end-to-end

ZoneManagementScreen lists zones from getTablesZoneDetails and saves through ZoneSave: with a zoneId it updates, without one it creates. TableConfigScreen loads every table from getTablesDetails and keeps the selected zone's tables, a filter that never matches today. It saves through tableSave. Home uses /api/restaurants/showDetails, which returns the active zones with their active tables and each table's latest running order.

What matters where you sit

POS API

  • Updates are scoped to the caller's restaurant. A miss is firstOrFail, caught and returned as a 500, not a 404.
  • Creating a table checks for a duplicate name within the zone; a rename doesn't. zoneId is never checked against zones.
  • getTables filters: tableId is ambiguous (500), and zoneId is compared as hex against binary. The join with orders returns one row per running order.
  • No role checks; no rate limits.

Data — MySQL

  • A zone's isActive, set through the API, cascades to all its tables, including deleted ones. A zone's isDelete doesn't cascade.
  • A tables.status outside 0–2 makes the Table model's match throw, which breaks showDetails and getTablesDetails.

POS app

  • Number(t.zoneId) === selectedZone.zoneId is never true with hex IDs (TBL-D1). Another case of the GUID-migration comparison problem; compare RST finding F1.
  • The zone slice's loading covers saves, so the whole screen turns into a loader. Zone add and rename errors are never shown.
  • A zone toggle reply has no tableCount, so the card shows Tables: 0.

Super-admin panel

No validation. The zone switch saves without cascading to tables. The table switch has no listener. updateTable writes every posted key as a column. Deleted rows are listed.

Integrations

None.

Accepted risks (do not "fix" without a new decision)

  • TBL-D1: Table Management always shows No Tables Found.
  • TBL-D2: no integrity checks: foreign or missing zones, zone delete leaving tables live, duplicate names on rename, any capacity, an unvalidated panel.
  • TBL-D3: any role can change zones and tables through the API.
  • TBL-D4: broken list filters and duplicate rows.
