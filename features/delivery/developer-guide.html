Feature developer guide · DLV

Delivery board

The Delivery Orders screen: listing home-delivery orders and moving them from Pending to Completed, with WhatsApp messages on the way.

v1 scope

Two use cases: open the board, and move a delivery order on. See the README. The spec records today's behaviour plus targets (re-synced 2026-11-24; the app part of DLV-D1 is fixed, the server is unchanged): DLV-D1 to D3 are To fix; DLV-D4 (no app path to create delivery orders) is accepted.

How it works end-to-end

The Home DELIVERY tile opens the board, which polls orders/channel/{channelId}. Card buttons post orders/update-status/{kotId} with the KOT stage; for 1, 3 and 4 the server sends a WhatsApp text.

What matters where you sit

POS API

  • The list query filters on orders.orderChannel, which the GUID schema lacks; the failure comes back inside a 200 (DLV-D1). Target: check the channel is the restaurant's Delivery channel (404), hex IDs, newest first.
  • The update casts the ID with (int); ID 0 matches some KOT of any restaurant, and the update then fails in strict mode with SQL text in the reply (DLV-D2).
  • No role, restaurant or stage check; any integer status (DLV-D2). Target: hex lookup on a delivery order of the restaurant (404), owner / waiter, 0–4, Pending→Accepted / Rejected, Accepted→Out for Delivery, Out for Delivery→Completed (409).
  • WhatsApp goes to a number fixed in the code (DLV-D3). Target: the order's customerPhone.

Data — MySQL

  • orderChannel exists only in the old integer migration, not in db_script.
  • Strict mode turns the number-cast warning in an UPDATE into error 1292.

POS app

  • The channel ID comes from Home's channel list by channelCode (fallback 3 only when missing); IDs stay strings (app part of DLV-D1 fixed).
  • Toasts show the order's hex ID as Order #<id>.
  • Complete Payment sets KOT status 3 only today; target: opens Bill Payment (DLV-D3).

Super-admin panel

None.

Integrations

WhatsApp Cloud API (WHATSAPP_API_URL, WHATSAPP_ACCESS_TOKEN); fixed recipient; failures only logged. Not reached today.

Accepted risks (do not "fix" without a new decision)
