Feature developer guide · PRN

Printer settings & printing

One receipt printer per device — Wi-Fi, Sunmi built-in or USB: find it, save it, test it, and the route every bill and KOT print takes to reach it.

v1 scope

Three use cases: find and save a printer, check and test print, print a bill or KOT. Device only, so there are tester cases only. See the README. The spec records today's behaviour plus targets (re-synced 2026-11-24): Sunmi and USB printers are new and spec'd as they are; PRN-D1, PRN-D2 and PRN-D4 are To fix; PRN-D3 stays accepted.

How it works end-to-end

The Printer screen stores { type: "wifi", ip, port }, { type: "sunmi" } or { type: "usb", deviceId? } in AsyncStorage (WIFI_PRINTER; old values without type are Wi-Fi). Every print button builds an 80 mm PDF and calls printPdf(). On Android with a saved printer it goes to WifiPrinter, SunmiPrinter or UsbPrinter, which render it to 576-dot images and print silently. On failure it alerts and opens Android's print screen (PdfPrint); Wi-Fi first scans the network.

What matters where you sit

POS app

  • The screen detects a built-in printer on open (Sunmi first, then USB) and only then shows the tabs.
  • Today a single address found after any Wi-Fi failure is printed to and saved with no prompt — even when the saved printer is just out of paper (PRN-D1).
  • The port isn't validated: Number(port) || 9100, no upper bound (PRN-D2).
  • The alert and the print screen open together; bill print errors use Share Failed (PRN-D2).
  • testPageHtml still interpolates ${probe}, so the page ends with false / true (PRN-D4).

Android native

  • WifiPrinterModule: reachability is a plain TCP connect (3 × 5 s), so any open port counts; paper / cover via SDK status -2 / -4; separate scan pool (64 threads, 0.5 s).
  • SunmiPrinterModule: binds Sunmi's service (3 s), checks state, prints one buffered strip, feeds 3 lines, cuts, waits up to 30 s.
  • UsbPrinterModule: any printer-class USB device; asks for permission (waits 30 s); ESC/POS raster + feed-and-cut; no paper / cover check.
  • ReceiptRaster: shared rendering; widens narrow pages and joins pages for Sunmi / USB.
  • PdfPrintModule resolves when the dialog opens, never with the outcome.

Integrations

SPRT printer SDK (com.printer.sdk), Sunmi printer library (com.sunmi.peripheral.printer), react-native-html-to-pdf, react-native-share (iOS fallback).

Accepted risks (do not "fix" without a new decision)

  • PRN-D1 (part): Search printers, Check connection and Test print treat any open port as a printer; a tapped search result is saved.
  • PRN-D2 (part): unreachable Invalid IP alert; print screen outcome unknown; Not reachable chip for any failed Wi-Fi test; iOS share sheet only.
  • PRN-D3: device-wide setting that survives sign-out and restaurant changes; chefs have no screen.
  • PRN-D4 (part): no USB paper / cover check; 30 s USB permission wait during a print; a vanished built-in printer fails each print.
