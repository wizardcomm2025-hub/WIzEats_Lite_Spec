Feature developer guide · IMPEX

Import & export

Bulk CSV import of zones and tables, menu, and floors and rooms, plus three header-only CSV templates. It is API-only today.

v1 scope

Two use cases: import CSV files and download a template. See the README. The spec records today's behaviour; IMPEX-D1 to D3 keep the current rules as accepted risks.

How it works end-to-end

ImportController validates up to three files (zone_file, menu_file, floor_file; csv/txt; 10 MB) and calls ImportService::import with the caller's restaurantId. Inside one transaction it reads each file by column position, skips the first line, finds or creates the parent by name, and creates one child per row. Every row has its own try / catch, so failures are logged and skipped. ExportService streams a single header line per template.

What matters where you sit

POS API

  • The response is always Import completed successfully, with no counts (IMPEX-D2).
  • The outer failure answers 400 with $e->getMessage() (IMPEX-D3).
  • No role check and no rate limit.

Data — MySQL

  • Parents are matched by name, ignoring case, among rows that aren't deleted; active state is ignored. Children are never de-duplicated.
  • (int) / (float) casts; createdBy is ignored where it isn't fillable.
  • Import uses real binary IDs, so the rooms it creates work, unlike ROOM's own API.

POS app

ImportExcelSection is commented out in Profile. It would send the field file and call a different export URL (IMPEX-D1).

Super-admin panel

None.

Integrations

Failures also go to the Google Sheet log service.

Accepted risks (do not "fix" without a new decision)

  • IMPEX-D1: no UI.
  • IMPEX-D2: silent skips, no counts, duplicates on re-import.
  • IMPEX-D3: no value checks, any role, raw exception text, empty templates only.
